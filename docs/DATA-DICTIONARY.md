# 访视与冻结定义

样例均为虚构编号，无身份信息。受试者入组日期由subjects表唯一确定，记录中的入组基准必须完全一致。采样日期和入组日期均转为Asia/Shanghai日历日期，差值为访视日；时刻先统一UTC。
方案选择按当前受试者assignment和该次发生时刻查半开生效窗，匹配必须唯一，不能使用全局最新方案。v1访视V1=[5,10)、V2=[12,17)；v2为[6,11)、[13,18)。受试者00001于10月10日转v2，其他受试者仍用v1。
PRIMARY计入访视完成，RETEST只替代该次测量值。首次记录必须唯一且在访视窗内。缺首次访视、重复首次和窗外访视均阻断，复检不能填补漏访或消除原偏离。
复检须引用同受试者同访视的PRIMARY，晚于原采样且不超过72小时，版本必须更高。同最高版本复检冲突时保留原结果并阻断。所有检验值以mg/dL输出，g/L乘100。
锁库须所有规定访视完成，无偏离、复检问题和隔离行。冻结包包含每条选定结果、原始行号、方案版本与访视窗。此工具只验证试验数据完整性，不做诊断判断或生产锁库。

## 药物交接

交接回传字段：`event_id`（事件号）、`subject`、`visit`、`box`（药盒号）、`action`、`at`、`evidence`（凭证号）、`replaces`（被替换旧盒）、`protocol`。`action` 取值 `DISPENSE` 发药、`RETURN` 回收、`DESTROY` 中心销毁、`EXCURSION` 温控超限、`REPLACE` 换发。时刻按当时受试者有效方案校验，交接时点方案与申报不符的行隔离。空文件、坏表头、坏行都不吞证据：文件级问题记 `file_issue` 并阻断，行级问题进交接隔离并保留原始行。

结算单位是“计划访视”，不是总量也不是单盒：
- 访视完成且该访视发出的每盒都有终态，才记“已结清”；
- 终态为：已回收（`RETURN` 且有凭证）、已销毁（`DESTROY` 且有凭证）、已换发（旧盒有 `REPLACE` 且超限有凭证）。销毁与换发自身即依据，不要求先回收；
- 只有发药、无任何终态的药盒记“手中”，访视阻断；回收/销毁/超限凭证为空亦阻断；
- 换发未写 `replaces`、旧盒无发药记录、换发链断开或成环，按去向缺失阻断；
- 同一回传重试（同事件号同内容，或同受试者同访视同盒同动作同内容）只计一盒，重试行单独留档；内容不同则按重复冲突隔离全部原行。

访视未完成时，发药结论沿用偏离模块的 `MISSING_PRIMARY` / `WINDOW_*` 同一原因码，标记 `shared` 并不重复计入锁库阻断总量；药盒级新问题以 `DISPENSE_*` 进入偏离页并计入锁库。页面同时给出手中、已销毁、已回收、已换发、去向缺失数量。重算失败保留旧批结论与旧批号，不覆盖历史。
